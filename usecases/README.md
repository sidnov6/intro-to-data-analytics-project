# Use-Case Proposals

This folder is the team's idea board. Add **one Markdown file per idea**. Do not delete rejected ideas: update their status so the reasoning remains visible.

## Add an idea

1. Copy [`TEMPLATE.md`](TEMPLATE.md).
2. Save it as `your-name-short-title.md`.
3. Replace all placeholders and include direct links to candidate data.
4. Make the research question specific enough to test.
5. Open a pull request and request teammate feedback.

## Minimum standard for discussion

A proposal is ready for the selection meeting only if it includes:

- a one-sentence research question;
- a target outcome or clearly defined analytical objective;
- the unit of analysis;
- at least one plausible data source with a working link;
- expected time coverage and approximate sample size, labelled as estimated until verified;
- a baseline and proposed evaluation metric;
- major access, privacy, licence, ethics, and feasibility risks; and
- a smallest useful version that can be finished on time.

## Status values

- `draft` — author is still completing it
- `ready-for-review` — meets the minimum standard
- `shortlisted` — selected for a data-feasibility check
- `selected` — chosen by the team
- `not-selected` — retained for decision history

## Selection process

1. Read every `ready-for-review` proposal.
2. Ask questions in the proposal's pull request or issue.
3. Score each idea using [`SCORECARD.md`](SCORECARD.md).
4. Run a small real-data feasibility check for the strongest candidates.
5. Choose one primary project and, only if useful, one fallback.
6. Record the decision and evidence in [`docs/decisions/`](../docs/decisions/README.md).

Do not start full modelling before the data-feasibility gate passes.
