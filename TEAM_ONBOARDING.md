# Team Onboarding

The repository is currently public, so anyone with the link can view and clone it. Public access does not grant permission to edit the main repository directly.

## Giving teammates direct editing access

1. Ask each teammate for their exact GitHub username or account email.
2. Open the repository on GitHub.
3. Go to **Settings → Collaborators → Add people**.
4. Invite each teammate.
5. Ask them to accept the GitHub invitation. They can then create branches and contribute directly.

GitHub's current instructions are in [Inviting collaborators to a personal repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository).

## New teammate

1. Open the public repository link. If invited as a collaborator, also accept the GitHub invitation.
2. Open the repository and read `README.md`, `COURSE_REQUIREMENTS.md`, and `PROJECT_CHARTER.md`.
3. Add your first idea using `usecases/TEMPLATE.md` and `usecases/README.md`.
4. Request a teammate review.

Without a collaborator invitation, a teammate can still fork the public repository and propose changes through a pull request.

## Local setup after the topic is selected

The repository will gain project-specific environment and run instructions after the selected use case passes its data-feasibility check. Until then, teammates can contribute proposals entirely through the GitHub website; no programming setup is required.
