## What the project must demonstrate

The course is about completing and communicating an end-to-end data analytics project. Our repository should provide clear evidence of:

- a focused and answerable research question;
- justified data collection and source selection;
- reproducible data cleaning and preparation;
- exploratory analysis that informs, rather than replaces, the main analysis;
- appropriate feature selection or construction;
- a suitable analytical method, such as regression or classification where the question calls for it;
- a simple and meaningful baseline;
- a defensible train/validation/test or other evaluation design;
- correctly chosen metrics and honest interpretation;
- readable Python/source code;
- clear figures, tables, conclusions, and limitations;
- a presentation every team member can explain and defend; and
- transparent acknowledgement of AI assistance and human review.

## Evidence checklist

Before submission, the repository should contain:

- [ ] Final problem statement and research question
- [ ] Data-source register with working links, ownership, access date, licence/usage notes, coverage, and limitations
- [ ] Data dictionary
- [ ] Reproducible setup instructions
- [ ] Cleaning and quality checks
- [ ] Exploratory analysis
- [ ] Baseline analysis or model
- [ ] Main analysis/model and comparison
- [ ] Evaluation on data not used to choose the final method
- [ ] Figures and tables with units, labels, and sample sizes
- [ ] Limitations, ethics/privacy discussion, and scope of claims
- [ ] Micropublication/final report
- [ ] Source code and notebooks that run in a documented order
- [ ] 20-minute presentation and 10-minute Q&A preparation
- [ ] AI-assistance record
- [ ] Final teammate review and rehearsal

## Quality gate

The project is not ready merely because a model runs. It is ready when a teammate can answer:

1. What exactly are we trying to learn or predict?
2. Who would care about the answer, and why?
3. What is one observation in our dataset?
4. Where did every important field come from?
5. What could make our conclusion wrong?
6. Why is our evaluation fair?
7. What does the main metric mean in plain language?
8. Which claims are supported, and which are not?
9. Can the analysis be rerun from the repository instructions?
